## 1. 背景与目标

### 1.1 背景

平台当前基于 K8s 架构，所有模型服务以 Pod 形态调度。新项目现场与现有架构存在以下差异：

1. 现场没有 K8s 环境，运维习惯是 Docker 直接部署，短期内不会建设集群；
2. 业务不允许停服，把现有容器迁到 K8s 的改造成本和风险都不可接受；
3. 现场已有大量以 Docker 启动的模型容器，必须原样保留，不能因纳管而重建。

因此需要平台在 K8s 之外，直接把「一台装有 Docker 的主机」当作运行环境纳管进来。

### 1.2 目标

在**不改动客户现有环境**的前提下，新增「Docker 主机」作为与 K8s 集群并列的运行环境：

1. 管理员可以注册多台 Docker 主机，平台展示其在线状态、加速卡与运行实例；
2. 模型服务可以容器形态部署到指定主机，并执行启动 / 停止 / 编辑 / 删除；
3. 工作台、集群与主机、部署弹窗、服务列表四个位置同时呈现两种运行环境，用户在一个平台内统一查看与操作。

### 1.3 设计原则

| 原则         | 说明                                                                                   |
| ------------ | -------------------------------------------------------------------------------------- |
| 轻纳管       | 平台只做连通、纳管、监控与实例启停；不做环境改造、不做 Agent 全生命周期管理、不做迁移    |
| 不侵入       | 纳管过程不修改主机上已有的 Docker 配置，不重建已有容器，不接管非平台部署的容器           |
| 核心不感知   | 平台核心逻辑不感知运行时差异，通过统一 Runtime 接口 + K8s / Docker 适配器实现              |
| 能力显式收口 | Docker 不具备的能力（在线扩缩容、跨主机重调度等）在界面上明确提示并禁用，不做隐性降级     |

## 2. 核心概念

| 概念                 | 定义                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| 运行环境（Runtime）  | 模型服务的运行载体，取值 `k8s`（K8s 集群）或 `docker`（Docker 主机）。平台核心不感知具体运行时。          |
| Docker 主机          | 一台安装了 Docker、被平台注册纳管的主机，是 Docker 运行环境下的部署目标。                                 |
| yl-agent             | 部署在 Docker 主机上的轻量代理，负责部署、启停、状态上报、加速卡挂载。平台通过它操作主机上的容器。         |
| 运行实例             | 模型服务在一个运行环境中的一个容器 / Pod。Docker 服务每个实例对应主机上一个容器。           |
| 平台部署实例         | 由平台通过部署弹窗创建的实例。主机上其他来源的容器不计入，也不受平台管理。                 |
| 轻纳管               | 见 1.3。                                                                                                |
| 部署目标             | K8s 下为集群，Docker 下为主机。由部署弹窗的「部署目标」下拉选择。                                         |

### 2.1 Docker 主机状态机

| 状态   | 进入条件                                   | 可执行操作             | 界面表现                 |
| ------ | ------------------------------------------ | ---------------------- | ------------------------ |
| 安装中 | 提交注册，平台正在安装 Agent 并建立连接     | 无（等待）             | 灰色 badge，列表黄色状态点 |
| 在线   | Agent 上线并开始心跳                       | 移除、被选为部署目标   | 绿色 badge，列表绿色状态点 |
| 离线   | 心跳超时                                   | 移除                   | 红色 badge，列表红色状态点 |
| 已移除 | 管理员确认移除，且主机上无平台部署的运行实例 | —                      | 从列表消失               |

说明：

- 「安装中 → 在线」为正常路径；安装失败的处理见 5.2.4；
- 离线主机**仍保留在列表中**，不被自动移除；其上已部署的实例状态见 5.4.2；
- 离线主机不能作为新部署的目标。

## 5. 需求详情

### 5.1 工作台与监测

#### 5.1.1 页面说明

- 页面位置：工作台 > 系统概览。
- 操作人：所有登录用户（只读 + 筛选）。

#### 5.1.2 业务规则

1. **运行环境筛选**：显卡资源区新增「运行环境」下拉，选项为 全部环境 / K8s 集群 / Docker 主机，默认「全部环境」。
2. **下拉联动**：「运行环境」变化时，「集群 / 主机」下拉按 5.1.3 联动。
3. **表格筛选**：「运行环境」与「集群 / 主机」共同作为卡级明细表的筛选条件；表格本身不单设「运行环境」列。
4. **在线指标拆分**：「在线节点 / 主机」指标下方展示 `K8s 节点 N` 与 `Docker 主机 M` 两项。
5. **历史预警**：「预警规则配置」旁新增「历史预警」入口，弹窗列为 触发时间 / 级别 / 预警项 / 对象 / 详情，每页 6 条，无筛选、无搜索、无持续时长 / 状态列。
6. **预警范围不变**：预警体系仍只覆盖 K8s 集群，不新增 Docker 主机类预警（主机离线不触发平台预警，仅在集群与主机页以状态点体现）。

#### 5.1.3 下拉联动规则

| 运行环境   | 「集群 / 主机」下拉标签 | 下拉选项                               |
| ---------- | ---------------------- | -------------------------------------- |
| 全部环境   | 集群 / 主机            | 全部 + 所有集群 + 所有主机             |
| K8s 集群   | K8s 集群               | 全部 + 仅集群                          |
| Docker 主机 | Docker 主机            | 全部 + 仅主机                          |

- 切换运行环境后，若当前已选的集群 / 主机不在新选项范围内，自动回落到「全部」。
- 没有任何 Docker 主机时，选「Docker 主机」后明细表为空，不报错。

#### 5.1.4 验收要点

- [ ] 切换运行环境为 Docker 主机后，明细表只出现 Docker 主机的卡；切回全部环境恢复。
- [ ] 切换运行环境后，「集群 / 主机」下拉的标签与选项同步变化。
- [ ] 历史预警弹窗分页正确，无筛选 / 搜索控件。

#### 5.2.3 注册 Docker 主机

**弹窗字段**

| 字段         | 必填 | 默认值 | 校验                                   | 说明                          |
| ------------ | ---- | ------ | -------------------------------------- | ----------------------------- |
| 主机 IP      | 是   | —      | IPv4 格式                               | 主机的管理 IP                  |
| 主机名称     | 否   | —      | —                                      | 留空时自动生成 `docker-host-<IP 末段>` |
| SSH 端口     | 否   | 22     | 数字                                    |                               |
| SSH 账号     | 否   | root   | —                                      |                               |
| SSH 密码 / 密钥口令 | 否 | —    | —                                      | 密码输入框，不回显             |

**流程**

1. 点击「注册主机」→ 打开弹窗，表单重置为默认值；
2. 填写后点击「开始注册」→ 前端校验 IP；通过后按钮置灰，弹窗保持打开；
3. 主机以「安装中」状态**追加**到列表末尾并自动选中，Tab 计数 +1；
4. 平台通过 SSH 安装 Agent 并建立连接；成功后主机转为「在线」，刷新加速卡信息，弹窗自动关闭，toast「主机注册完成，Agent 已上线，可承接部署」。

**规则**

- 注册是**追加**，不影响已纳管的其他主机；
- 主机数量上限本期不限；
- 同一 IP 重复注册的处理见 5.2.4；
- 弹窗底部提示「注册过程预计需要 1–2 分钟」；弹窗内**不展示**进度条与 Agent 安装说明。

#### 5.2.4 异常与边界

| 场景                       | 处理                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------- |
| IP 格式非法                | 字段下方红字提示「请填写主机 IP」，输入框聚焦，不提交                                   |
| IP 已被纳管                | 提示「该主机已注册」，不重复添加                                                        |
| SSH 连接失败 / 安装失败    | 主机从列表移除，toast 报错（建议含失败原因）；弹窗保持打开允许重试                      |
| 注册超时（建议 > 3 分钟）  | 同上，按失败处理                                                                       |
| 主机离线                   | 保留在列表中；不可作为部署目标；可移除                                                  |
| 移除时主机仍有运行实例     | 阻止移除，toast「该主机仍有 N 个运行中的实例，请先停止或迁移」                          |
| 同一主机的实例全部停止后   | 可以移除                                                                                |

#### 5.2.5 移除主机

- 入口：右侧概览卡「移除主机」按钮，作用于**当前选中的主机**；
- 弹窗：展示「即将移除：名称 (IP)」，并根据实例数提示（有实例：「该主机仍有 N 个运行实例，需先停止或迁移后才能移除」；无实例：「移除后主机不再接受新部署」）；
- 确认后：从列表移除，Tab 计数 −1，自动选中列表首台；若无主机则进入空态；
- 移除**不停止**主机上的容器，**不修改**主机 Docker 配置；仅平台侧解除纳管；
- 移除后，该主机上已停止的 Docker 服务记录保留在模型服务列表，运行环境显示原 IP，不可再启动（需重新注册该主机）。

#### 5.2.6 验收要点

- [ ] 注册成功后主机出现在列表末尾并被选中，Tab 计数 +1；
- [ ] 切换左侧主机，右侧概览同步变化，离线主机显示红色 badge；
- [ ] 移除有实例的主机被阻止；移除无实例主机成功且选中首台；
- [ ] 移除全部主机后显示空态与注册入口；
- [ ] 概览卡不出现 CPU / 内存 / Agent / 共享存储 / 环境预检。

### 5.3 部署弹窗

#### 5.3.1 页面说明

- 入口：模型服务列表 > 部署服务；或服务行 > 编辑（仅已停止的 Docker 服务）。
- 操作人：管理员（一级）。

#### 5.3.2 表单结构

部署位置为两级选择：

| 字段           | K8s 集群                          | Docker 主机                                             |
| -------------- | --------------------------------- | ------------------------------------------------------- |
| 部署运行环境   | 单选（默认）                      | 单选                                                    |
| 部署目标       | 集群列表                          | **在线**主机列表，显示 `IP · 名称（型号 × 卡数）`       |
| 加速卡         | 展示选卡面板、GPU 型号行、节点模式 | 隐藏以上三项，改为展示「实例上限提示」                  |
| 副本数 / 每副本卡数 | 不变                         | 不变；任一变化时实时重算上限                            |

其余字段（模型、版本、运行配置等）与 K8s 部署保持一致。

#### 5.3.3 业务规则

1. **目标列表**：只列出在线主机；没有任何在线主机时「部署目标」为空并提示先注册主机。
2. **能力差异提示**：选择 Docker 时展示说明条——「实例直接运行于主机 Docker，不经过 K8s 调度。不支持跨主机自动重调度，主机离线时实例不可用；不支持在线扩缩容，实例数在部署时确定。」
3. **实例上限**：设主机总卡数 `T`、已用 `U`、每副本卡数 `P`、副本数 `R`：
   - 空闲卡 `F = T − U`；
   - 单机最大实例数 `M = ⌊T / P⌋`，当前空闲可支持 `K = ⌊F / P⌋`；
   - 提示文案：「Docker 主机单机容量：每副本 P 卡时最多 M 个实例（当前空闲卡可支持 K 个），加速卡由平台按顺序自动分配。」
   - 当 `R × P > F` 时红字提示「需要 R×P 张卡，但该主机仅剩 F 张空闲，请调整副本数或更换主机」，**阻止提交**。
4. **加速卡分配**：平台按顺序自动分配，不提供选卡网格。
5. **部署进度**：提交后依次 拉取镜像 → 创建容器 → 健康检查；全部完成后关闭弹窗并跳转到服务列表。
6. **编辑模式**：仅已停止的 Docker 服务可编辑；提交后提示「配置已更新，重启实例后生效」。

#### 5.3.4 验收要点

- [ ] 切换运行环境，部署目标下拉、能力提示条、选卡面板与上限提示同步切换；
- [ ] 修改副本数或每副本卡数，上限提示实时更新；
- [ ] 超出空闲卡时红字提示且无法提交；
- [ ] 运行中的 Docker 服务行不出现「编辑 / 扩缩容」。

### 5.4 模型服务列表

#### 5.4.1 页面说明

- 页面位置：模型管理 > 模型服务。
- 操作人：管理员（一级）。

#### 5.4.2 服务状态与操作矩阵

| 服务状态 | 运行环境 | 可见操作               | 说明                                 |
| -------- | -------- | ---------------------- | ------------------------------------ |
| 运行中   | K8s      | 扩缩容、停止           | 与现状一致                            |
| 运行中   | Docker   | 停止                   | 不显示编辑、扩缩容、日志、蓝绿更新    |
| 已停止   | K8s      | 删除、编辑、启动       | 与现状一致                            |
| 已停止   | Docker   | 删除、编辑、启动       |                                      |

补充规则：

- Docker 服务「运行中 / 已停止」的定义：至少一个容器在运行为运行中；全部容器停止为已停止；
- 所在主机离线时，服务状态建议标记为「不可用」（实例不可访问），恢复心跳后自动回到运行中；本期原型未画此状态，研发可按后端实际能力决定是否展示；
- 「停止」会释放该服务占用的加速卡，主机概览的「加速卡 已用」随之减少。

#### 5.4.3 操作规则

| 操作 | 适用状态       | 确认   | 结果                                                   | 异常                                   |
| ---- | -------------- | ------ | ------------------------------------------------------ | -------------------------------------- |
| 停止 | 运行中         | 需要   | 所有容器停止，状态 → 已停止，toast「容器已停止，所占加速卡已释放」 | —                                      |
| 启动 | 已停止         | 需要   | 按原配置重新创建容器，状态 → 运行中                     | 主机离线或空闲卡不足时阻止并提示        |
| 编辑 | 已停止         | 不需要 | 打开部署弹窗（configure 模式），目标主机不可更换         | 运行中不展示编辑入口                    |
| 删除 | 已停止 / 运行中 | 需要  | 删除容器与服务记录，释放加速卡                         | —                                      |

#### 5.4.4 验收要点

- [ ] 运行环境列与筛选正常，Docker 服务显示 Docker pill；
- [ ] 运行中的 Docker 服务只有「停止」；
- [ ] 停止后主机概览「运行实例」与「加速卡 已用」同步减少；
- [ ] 已停止的 Docker 服务可编辑、可启动、可删除。

## 6. 非功能要求

| 类别       | 要求                                                                                   |
| ---------- | -------------------------------------------------------------------------------------- |
| 性能       | 主机列表 ≤ 50 台时页面首屏 ≤ 2 s；概览指标心跳刷新周期与 K8s 节点一致                  |
| 心跳与离线 | 建议心跳间隔 10 s、连续 3 次丢失判离线；离线判定延迟 ≤ 30 s                            |
| 注册超时   | 建议单台注册超时 3 min；超时按失败处理                                                 |
| 安全       | SSH 密码仅用于注册期安装 Agent，不落库明文（加密存储或注册后销毁）；页面不回显           |
| 兼容性     | 不校验 Docker 版本 / 驱动；Agent 需兼容主流 Linux 发行版与 Docker 版本（具体范围研发定） |
| 不侵入     | 纳管过程不修改 `/etc/docker/daemon.json` 等现有配置，不操作非平台容器                   |
| 权限       | 注册 / 移除主机、部署 / 启停 / 删除服务仅管理员（一级）可操作                            |
| 数据一致性 | 主机、服务、实例三处的加速卡计数需一致；移除主机前必须二次校验无运行实例                 |
